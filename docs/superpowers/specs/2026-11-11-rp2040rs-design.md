# rp2040rs: Rust port of rp2040js — design

- Status: approved in chat on 2026-11-11
- Upstream reference: `wokwi/rp2040js` v1.4.1,
  commit `8693315df527adce8bf2bc315aeb4a1ca61c02a3`
- Upstream license: MIT (Uri Shaked and contributors)
- Deliverable: Rust library crate plus `rp2040rs` CLI. Full `src/` behaviour and
  all `src/index.ts` exports, including GDB server, Simulator, USB, and the

## 2. Non-goals

- JavaScript, WebAssembly, or Node native bindings. The upstream tests are
  ported, not executed unchanged against Rust.
- The upstream browser demo, `@wokwi/elements` integration, and the demo
  scripts under `demo/`.
- Bit-for-bit JavaScript object identity, property descriptors, or prototype
  semantics. Rust naming, ownership, and callable shapes determine the API
  where JavaScript identity is not observable through simulation behaviour.
- LittleFS image creation, MicroPython/CircuitPython filesystem tooling, or
  host filesystem emulation beyond loading flash images.
- Multi-threaded `Send`/`Sync` state. The emulator is a single-threaded core;
  the GDB server is a blocking single-threaded event loop.

## 4. Architecture

### 4.1 Facade, bus, and shared board state

`Rp2040` is a cheaply cloneable facade. It owns a `Rc<RefCell<BoardShared>>`
and exposes cloned peripheral handles:

```rust
#[derive(Clone)]
pub struct Rp2040 {
    pub core: Core,
    pub uart: [Uart; 2],
    pub i2c: [I2c; 2],
    pub gpio: [GpioPin; 30],
    pub qspi: [GpioPin; 6],
    pub dma: Dma,
    pub pio: [Pio; 2],
    pub usb_ctrl: UsbController,
    pub spi: [Spi; 2],
    pub clocks: Clocks,
    pub pll_sys: Pll,
    pub pll_usb: Pll,
    pub ppb: Ppb,
    pub sio: Sio,
    pub pwm: Pwm,
    pub adc: Adc,
    pub timer: Timer,
    pub watchdog: Watchdog,
    pub rtc: Rtc,
    pub xosc: Xosc,
    pub psm: Psm,
    pub resets: Resets,
    pub syscfg: SysCfg,
    pub sysinfo: SysInfo,
    pub tbman: Tbman,
    pub busctrl: BusCtrl,
    pub pads: [Pads; 2],
    pub io: Io,
    pub ssi: Ssi,
    pub interpolator: Interpolator,
    pub bootrom: Memory,
    pub sram: Memory,
    pub flash: Memory,
    pub usb_dpram: Memory,
    shared: Rc<RefCell<BoardShared>>,
}
```

`BoardShared` stores the shared bus and host state:

- `bootrom`, `sram`, `flash`, and `usb_dpram` memory handles;
- `clk_sys`, `clk_peri`, `xosc_freq`, `rosc_freq`;
- the `Clock` handle, logger, clock-listener registry;
- the `Core` handle and concrete handles that bus logic must notify directly
  (`uart`, `pwm`, `ppb`, `sio`, `usb_ctrl`);
- a `BTreeMap<u32, Rc<dyn Peripheral>>` registry keyed exactly like upstream:
  `(address >> 14) << 2`;
- `on_break` callback.

`Bus` is a cloneable newtype over the same `Rc<RefCell<BoardShared>>`. Core and
peripherals hold a `Weak` reference to the shared board and upgrade it only for
the duration of a bus operation. `Rp2040::read_u32` and the other public bus
methods delegate to `Bus`. This avoids ownership cycles:

```text
Rp2040 ──strong──> BoardShared ──strong──> Core, Uart, Pio, ...
   │                   ▲                         │
   └──strong──> handles └────────weak───────────┘
```

### 4.2 Peripheral state cells

Every peripheral is a cloneable handle over its own
`Rc<RefCell<PeripheralState>>` plus a `Weak<RefCell<BoardShared>>`. The handle
implements:

```rust
pub trait Peripheral {
    fn name(&self) -> &'static str;
    fn read_u32(&self, offset: u32) -> u32;
    fn write_u32_atomic(&self, offset: u32, value: u32, atomic_type: u32);
    fn reset(&self) {}
}
```

`BasePeripheral` provides the upstream default behaviour: warning on
unimplemented reads, `0xffff_ffff` for unimplemented reads, warning on
unimplemented writes, and `raw_write_value` storage for atomic operations.
Concrete peripherals either embed `BasePeripheral` and delegate through a small
macro, or implement the trait directly.

The registry stores `Rc<dyn Peripheral>`. Built-in peripherals are registered at
their upstream keys; `Rp2040::set_peripheral(key, peripheral)` replaces or adds
an entry for tests. This reproduces upstream's `peripherals[0x10] = ...` and
`vi.spyOn` cases without exposing mutable board internals.

### 4.3 Re-entrancy rules

The implementation must never hold a `RefCell` borrow of `BoardShared` while
calling a peripheral, clock alarm, listener, or host callback. The sequence is
always:

1. borrow the registry/state briefly to clone the needed handle or take a
   callback;
2. drop the borrow;
3. invoke the handle or callback.

Peripheral methods may then re-enter `Bus` through their weak reference. State
cells that are temporarily moved out for a callback are restored by a drop
guard, so a panic cannot permanently remove the callback.

### 4.4 Clocks and alarms

`Clock` mirrors upstream `IClock`:

```rust
pub trait Clock: 'static {
    fn nanos(&self) -> f64;
    fn create_alarm(&self, callback: Box<dyn FnMut()>) -> Alarm;
}
```

`SimulationClock` stores a sorted alarm list in
`Rc<RefCell<SimulationClockState>>` and returns cloneable `Alarm` handles.
`Alarm::schedule(delta_nanos)` and `Alarm::cancel()` update the list.
`SimulationClock::tick(delta_nanos)` extracts all due callbacks, releases the
borrow, invokes each callback in due-time order, then advances the counter.
`MockClock::advance(micros)` is the test clock.

## 5. Public API

### 5.1 `Rp2040`

```rust
impl Rp2040 {
    pub fn new() -> Rp2040;
    pub fn with_clock(clock: Rc<dyn Clock>) -> Rp2040;
    pub fn reset(&self);
    pub fn load_bootrom(&self, data: &[u32]);

    pub fn read_u32(&self, address: u32) -> u32;
    pub fn read_u16(&self, address: u32) -> u16;
    pub fn read_u8(&self, address: u32) -> u8;
    pub fn write_u32(&self, address: u32, value: u32);
    pub fn write_u16(&self, address: u32, value: u16);
    pub fn write_u8(&self, address: u32, value: u8);

    pub fn step(&self);
    pub fn execute_instruction(&self) -> u32;
    pub fn clk_sys(&self) -> f64;
    pub fn clk_peri(&self) -> f64;
    pub fn set_xosc_freq(&self, hz: f64);
    pub fn set_rosc_freq(&self, hz: f64);

    pub fn add_clock_listener(
        &self,
        listener: Box<dyn FnMut(f64, f64)>,
    ) -> ClockListenerId;
    pub fn remove_clock_listener(&self, id: ClockListenerId) -> bool;
    pub fn set_peripheral(&self, key: u32, peripheral: Rc<dyn Peripheral>);
    pub fn set_logger(&self, logger: Box<dyn Logger>);
    pub fn set_on_break(&self, callback: Box<dyn FnMut(u32)>);
    pub fn gpio_values(&self) -> u32;
    pub fn set_interrupt(&self, irq: u32, value: bool);
    pub fn update_io_interrupt(&self);
}
```

`update_clocks()` recomputes `clk_sys` and `clk_peri` from CLOCKS/PLL state,
updates SysTick and PWM timers, notifies UARTs of `clk_peri` changes, and invokes
clock listeners only when a frequency actually changes. A source that is
unknown or unconfigured keeps the last known good frequency, matching upstream.

### 5.2 Core and memory accessors

`Core` exposes the state required by the upstream test driver and GDB:

- `pc`, `set_pc`, `sp`, `set_sp`, `lr`, `reg`, `set_reg`, `xpsr`, `set_xpsr`;
- flags `n`, `z`, `c`, `v` and setters;
- `read_special_register`, `write_special_register`;
- `set_interrupt(irq, value)`, `waiting()`, `break_rewind()`;
- `execute_instruction() -> u32` (cycle count) and `step()`.

`Memory` wraps `Rc<RefCell<Vec<u8>>>`:

```rust
impl Memory {
    pub fn len(&self) -> usize;
    pub fn borrow(&self) -> Ref<'_, Vec<u8>>;
    pub fn byte(&self, index: usize) -> u8;
    pub fn set_byte(&self, index: usize, value: u8);
    pub fn copy_from_slice(&self, offset: usize, data: &[u8]);
    pub fn fill(&self, value: u8);
}
```

`flash` is 16 MiB, `sram` is 264 KiB, `bootrom` is 4 KiB, and `usb_dpram` is
4 KiB. `load_bootrom` writes little-endian words and calls `reset()`.

### 5.4 Callbacks and listeners

Notification-only callbacks keep their upstream argument lists:

- `Uart::set_on_byte(Box<dyn FnMut(u8)>)`
- `Uart::set_on_line(Box<dyn FnMut(&str)>)`
- `UsbCdc::set_on_serial_data(Box<dyn FnMut(&[u8])>)`
- `UsbCdc::set_on_device_connected(Box<dyn FnMut()>)`

Callbacks that may re-enter the simulator receive an `Rp2040` clone or a
`&Rp2040` argument supplied by the caller:

- `GpioPin` listeners: `Box<dyn FnMut(&Rp2040, bool)>`
- USB setup/endpoint callbacks: `Box<dyn FnMut(&Rp2040, ...)>`
- clock alarms: `Box<dyn FnMut()>` closures that may hold an `Rp2040`
- `on_break`: `Box<dyn FnMut(u32)>`

Listeners that upstream removes by function identity use stable IDs:
`add_clock_listener` returns `ClockListenerId`; `GpioPin` listeners return
`ListenerId`.

## 6. Memory map and bus semantics

Constants match upstream:

```text
FLASH_START_ADDRESS = 0x1000_0000
FLASH_END_ADDRESS   = 0x1400_0000
RAM_START_ADDRESS   = 0x2000_0000
APB_START_ADDRESS   = 0x4000_0000
DPRAM_START_ADDRESS = 0x5010_0000
SIO_START_ADDRESS   = 0xd000_0000
```

`read_u32` dispatch order is bootrom, flash (four mirrors selected with
`address & 0x00ff_ffff`), SRAM, USB DPRAM, PPB (`address >> 12 == 0xe000e`),
SIO (`SIO_START_ADDRESS..SIO_START_ADDRESS + 0x1000_0000`), then the APB
peripheral registry. Unmapped reads log a warning and return `0xffff_ffff`.

Bus address handling must preserve these exact upstream masks:

- peripheral registry key: `(address >> 14) << 2`;
- peripheral read offset: `address & 0x3fff`;
- peripheral write offset: `address & 0xfff`;
- atomic type: `(address & 0x3000) >> 12`.

Atomic type values are normal `0`, XOR `1`, set `2`, clear `3`.
`atomic_update(current, kind, value)` uses XOR, OR, and AND-NOT respectively.

Memory writes:

- `write_u8` and `write_u16` to a peripheral replicate the value four times or
  twice and call `write_u32_atomic`;
- SRAM byte/halfword writes go directly to SRAM;
- a halfword at offset 3 spans two words and is split into byte writes;
- accesses that run past a region end do not panic;
- flash is initialized to `0xff`, while bootrom, SRAM, and USB DPRAM start
  zeroed.

`reset()` resets the core, resets PWM, and refills flash with `0xff`, exactly
as upstream.

## 7. CPU model

`CortexM0Core` implements the ARMv6-M instruction interpreter used by the 126
instruction tests. This includes:

- arithmetic, logical, shift, compare, branch, load/store, stack, push/pop,
  PC-relative `adr`, `add pc`, `bx`, `bl`, `blx`, `bkpt`;
- APSR flags N/Z/C/V with the upstream carry/overflow rules;
- MSP/PSP, PRIMASK, CONTROL, IPSR/EPSR, exception entry/return;
- NVIC `ISER`, `ICER`, `ISPR`, `ICPR`, `IPR` and pending/enabled/priority
  semantics;
- SysTick registers and PPB access;
- instruction cycle counts returned to `Simulator` and GDB stepping.

All 32-bit arithmetic uses explicit wrapping operations. Shifts handle counts
of 0 and 32 exactly as the upstream tests expect. `bkpt` sets `break_rewind`
and invokes `on_break`; GDB uses it to rewind PC for a stop report.

## 9. USB, GDB, Simulator, and CLI

### 9.1 USB

`UsbController` implements the RP2040 USB peripheral: endpoint control,
buffer-control registers, DPRAM transfers, USB enable/reset events, interrupt
endpoint addresses, host transaction alarms, and interrupt/status bits.

`UsbCdc` wraps a controller handle and reproduces the upstream enumeration
flow: descriptor request, configuration descriptor collection, endpoint
discovery, SET_CONFIGURATION, CDC SET_CONTROL_LINE_STATE, serial data callback,
and a 512-byte TX FIFO.

### 9.2 GDB

`GdbServer::process_message(&self, cmd: &str) -> Option<String>` contains the
upstream protocol logic and is directly testable. It supports:

`Hg0`, `?`, `qSupported`, `qAttached`, `qXfer:features:read:target.xml`,
`qRegisterInfo`, `qHostInfo`, `qProcessInfo`, `vCont?`, `vCont;c`,
`vCont;s`, `c`, `g`, `p`, `P`, `m`, `M`, and breakpoint stop reporting.

`GdbConnection` handles RSP framing (`$...#checksum`), acknowledgements, and
line assembly. `GdbTcpServer` uses `std::net::TcpListener` in blocking mode.
`GdbServer` registers an `on_break` callback that stops the target, rewinds PC
by `break_rewind`, and reports a stop reason. The server runs on one thread;
`continue` executes the target until a breakpoint or explicit stop, so no
`Send` state or background simulation thread is required.

`GdbTarget` is a trait with `rp2040()`, `executing()`, `execute()`, and
`stop()`, matching the upstream interface. `Simulator` implements it.

### 9.3 Simulator

`Simulator` owns an `Rp2040` and implements `GdbTarget`. It exposes:

```rust
pub fn new(clock: Rc<dyn Clock>) -> Simulator;
pub fn execute_once(&mut self);
pub fn run_until_stop(&mut self);
pub fn stop(&mut self);
pub fn executing(&self) -> bool;
```

`execute_once` runs at most 1,000,000 instructions, advancing the clock by
cycle nanoseconds or by the nanos to the next alarm when the core is waiting.
Unlike upstream, it does not schedule itself with `setTimeout`; the CLI or host
loop chooses when to call it again.

### 9.4 CLI

```text
rp2040rs --image <path> [--gdb] [--port 3333] [--expect-text TEXT]
```

- Load the embedded upstream bootrom B1, matching `demo/bootrom.ts`.
- Detect `.hex` and `.uf2` by extension, case-insensitively.
- Intel HEX: parse records 00/01/02/04/05, verify checksums, and write payload
  bytes at `load_address - 0x1000_0000` into flash.
- UF2: parse 512-byte blocks, validate the three magic words, and copy payload
  bytes at `flash_address - 0x1000_0000`.
- Set `PC = 0x1000_0000` after loading.
- Forward UART0 bytes to stdout.
- With `--gdb`, run the blocking GDB TCP server; without it, run the simulator
  loop directly.
- `--expect-text` scans the UART output, exits 0 on match, and exits 1 on
  EOF/no match. Missing image or malformed image exits 1 with a message.

Argument parsing uses `std::env`; the CLI has no external runtime dependencies.

## 10. Test port

- One `#[test]` per upstream `it`. `describe` blocks become nested `mod`
  blocks. Test names keep the upstream description in a Rust-friendly
  identifier, with the original text in a comment where ambiguity would
  otherwise be lost.
- `it.each` cases expand into separate tests. This is why the suite is 322,
  not 316.
- Async test-driver calls become synchronous method calls. `createTestDriver`
  becomes a `TestDriver` constructing an `Rp2040` or a GDB-backed driver; the
  default path is the in-process RP2040 driver.
- `vi.fn()` becomes a recorder struct. `vi.spyOn` behaviour is reproduced with
  `RecordingPeripheral` and `Rp2040::set_peripheral`.
- Exact integer comparisons use `assert_eq!`. Floating-point expectations use
  the upstream exact value when representable, otherwise an epsilon of
  `1e-6`.
- `src/test_support.rs` provides the test driver, register conversion helpers,
  assembler helpers, recording peripherals, and a `MockClock` convenience
  constructor. It is compiled under `cfg(test)` only.
- The 78-case assembler suite ports the opcode helper functions in
  `utils/assembler.ts` (`opcodeADCS` through `opcodeYIELD`), each returning the
  same 16- or 32-bit encoded word. rp2040js has no two-pass textual assembler.
  `utils/pio_assembler.rs` ports the PIO instruction encoders and constants
  (`pioJMP`, `pioWAIT`, `pioIN`, `pioOUT`, `pioPUSH`, `pioPULL`, `pioMOV`,
  `pioIRQ`, `pioSET`). Ported instruction tests build words with these helpers.

## 11. Documented parity differences

Simulation behaviour is determined by the 322 ported tests. The following API
shape differences are required by safe, idiomatic Rust and are recorded in
`docs/parity.md`:

1. Types and methods use Rust naming (`Rp2040`, `read_u32`, `clk_sys()`).
2. Direct JavaScript fields become accessors or `Memory` handles; `flash[3]`
   becomes `flash.borrow()[3]` or `flash.byte(3)`.
3. Callbacks that may re-enter the simulator receive an `Rp2040` handle.
4. Clock and GPIO listeners are removed by stable IDs rather than function
   identity.
5. Clock alarms are explicit handles rather than linked-list nodes.
6. GDB server and Simulator are single-threaded; GDB `continue` drives the
   target synchronously.
7. The emulator state is `Rc`-based and not `Send`/`Sync`.
8. `Simulator::execute` is replaced by explicit `execute_once`/`run_until_stop`.
9. JavaScript object identity and prototype/property semantics are not
   reproduced.
10. The CLI is native and std-only; it does not run the upstream TypeScript
    demo or open a browser.

Each module follows red-green porting: translate its upstream spec first, run
the ported tests against the new module, then implement until the module is
green. Upstream TypeScript sources are the behavioural reference whenever a
test expectation is ambiguous.

## 14. Risks and mitigations

- **RefCell re-entrancy**: separate peripheral state cells, weak board
  references, scoped registry borrows, and callbacks extracted before
  invocation. Every callback path gets a re-entrancy test.
- **JavaScript number semantics**: explicit `wrapping_add/sub/mul`, shifts with
  masked counts, `as i32` for signed comparisons, and `f64` where upstream uses
  fractional math. The 322 assertions are the primary regression gate.
- **PIO complexity**: port the 35 cases first, then fill autopull/autopush,
  stall, wrap, and IRQ edge cases while keeping the suite green.
- **USB timing**: endpoint alarms use the shared clock; tests cover descriptor
  extraction and the controller smoke path; no wall-clock dependency.
- **GDB has no upstream unit tests**: protocol handling is a pure function with
  command-level tests, plus a TCP integration smoke test. Divergence is limited
  to threading, which is documented.
- **Bootrom data**: embed the upstream B1 bootrom in a generated Rust data
  module and verify its length and first vector words in a test.
- **Scope size**: implement in the order above and finish one module at a time;
  no global big-bang integration. Release-mode test execution must remain
  bounded by the finite loops in the PIO, USB-alarm, and timer-alarm tests.
